# 단계 5 구현 설명: MTC 기반 Pick-and-Place

## 목적

이 문서는 `plan/moveit_apply.md`의 단계 5 구현에서 수정·생성·삭제한 파일과 각각의 역할 및 변경 이유를 정리한다. `pick_and_place_test.launch.py`가 기존 시뮬레이션을 시작하고 작업 노드가 준비 상태를 확인한 뒤 한 번 자동으로 Pick-and-Place를 수행한다. MoveIt Task Constructor(MTC)가 로봇 경로를 구간별로 계획·실행하고, 접촉·공 부착/분리·놓기 안정성은 Gazebo 상태를 확인해 처리한다. 성공과 실패 이후에도 시뮬레이션을 종료하지 않고 대기한다.

## 동작 흐름 요약

1. 통합 launch가 기존 시뮬레이션을 시작하고 작업 노드를 함께 실행한다.
2. 작업 노드는 컨트롤러, MoveIt 및 로봇/작업 장면 준비 조건을 timer callback으로 확인한다. 준비되면 한 번만 작업을 시작한다.
3. MTC의 계획·실행 구간과 Gazebo 물리 결과 확인을 교대로 수행한다. Gazebo 부착/분리 결과를 확인한 뒤 Planning Scene을 동기화한다.
4. 공 중심이 바구니 안쪽에 있고 추정 선속도가 기준 이하인 상태가 정해진 시간 지속될 때만 놓기를 성공으로 판정한다.
5. 성공 또는 실패 시 단계와 이유를 기록하고 대기한다. 자동 재시도나 launch 종료는 하지 않는다.

## 검증 및 범위

구현 당시 대상 패키지 빌드와 `colcon test`(6개 통과), launch Python/YAML 구문 검사, `git diff --check`를 통과했다. 격리된 Gazebo 통합 실행에서 접근부터 복귀까지 정상 완료하고 성공 후 프로세스가 유지되는 것을 확인했다. GUI의 RViz 수동 검토, 지연 action 승인 race, 놓기 경계·미안정 등 일부 실패 통합 시나리오는 별도 후속 검증 항목이다. 테스트 결과는 코드 변경 시점의 기록이며, 현재 환경에서 다시 실행한 결과를 뜻하지 않는다.

MTC가 기본 ROS 설치에 포함되지 않은 환경에서는 `package.xml` 의존성만으로 런타임 라이브러리가 자동 설치되는 것은 아니다. 문서화된 실행 이슈 안내를 참고해 rosdep/apt 의존성 설치 후 다시 빌드해야 한다.
