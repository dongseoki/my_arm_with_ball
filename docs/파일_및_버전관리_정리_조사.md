`README 필요성`은 README에 링크가 있는지와 실행에 필요한지를 구분한다. 루트 README는 프로젝트 내부 Markdown 문서로 연결되는 링크가 없으며, docs/plan/adr/analysis는 README 링크를 따라 도달하는 자료가 아니다. 다만 기술 설명 가치가 있는 자료는 실행 비필수여도 유지 대상으로 본다. 반대로 CMake의 디렉터리 전체 설치만 확인된 파일은 실행 중 소비된다고 판단하지 않는다.

- **확인 사실:** 추적 상태, 코드의 include/import, launch·설정·모델 URI, CMake 빌드/설치/시험 등록, 문서 참조.
- **권고 판단:** 면접관에게 보여줄 기술 가치와 공개 범위. 자동 분석으로 면접관의 평가를 보장할 수는 없다.
- **한계:** 정적 조사이며 이번에 ROS/Gazebo 런타임 시험을 실행하지 않았다. 외부 개인 스크립트, 저장소 밖 참조, Fuel 캐시 내부 파일과 Git 과거 전체 이력은 전수 조사 대상이 아니다. 생성물은 개별 내용을 해석하지 않고 범주·수량·추적 여부를 조사했다.

### 5.3 A 목록 적용 예시 — 아래 명령은 이번 작업에서 실행하지 않음

저장소 루트에서 실행하는 Bash 예시다. 현재 변경 내용을 먼저 확인하고 개인 파일을 저장소 밖에 백업한다. 실제 제외 대상만 명시하며 `git rm -r --cached .` 또는 `git add .`로 전체 인덱스를 다시 만들지 않는다.

```bash
git status --short

# 로컬 원본 보존용 백업. 파일 3개만 저장소 밖에 복사한다.
audit_backup_dir=$(mktemp -d /tmp/my_arm_private_docs.XXXXXX)
cp --parents -- AGENTS.md .github/copilot-instructions.md \
  trash/detail_plan.md "$audit_backup_dir"
printf '백업: %s\n' "$audit_backup_dir"

# 한 번만 추가한다. 같은 경로로 재생성돼도 실수로 add되지 않게 한다.
cat >> .gitignore <<'IGNORE'

# Local AI instructions and conversation archive
/AGENTS.md
/.github/copilot-instructions.md
/trash/detail_plan.md
# OMX local runtime data (also excluded locally via .git/info/exclude)
/.omx/
IGNORE

# --cached: 현재 작업 폴더의 원본을 남기고 인덱스에서만 제거
# -f를 쓰지 않음. 변경 충돌로 거부되면 중단하고 해당 diff를 확인한다.
git rm --cached -- AGENTS.md .github/copilot-instructions.md trash/detail_plan.md
git add -- .gitignore

# 원본 3개가 모두 남아야 함
for audit_path in AGENTS.md .github/copilot-instructions.md trash/detail_plan.md; do
  test -f "$audit_path" || break
  git check-ignore -v -- "$audit_path"
done

# 출력 없음 = 추적 해제 성공. 원본 존재 검사는 위에서 별도로 한다.
git ls-files -- AGENTS.md .github/copilot-instructions.md trash/detail_plan.md
git diff --cached --name-status
git diff --cached --check
```

성공 기준은 **세 원본 모두 존재, 세 경로의 `git ls-files` 출력 없음, staged diff에서 해당 세 파일의 삭제와 `.gitignore` 변경만 의도대로 확인**이다. 임시 백업은 재부팅/청소로 지워질 수 있으므로 장기 보관할 자료라면 별도 영구 저장 위치에도 보관한다. 이후 별도 커밋으로 기록해야 다음 공개 HEAD에서 제외된다. 단순 `.gitignore` 추가만으로는 기존 추적이 해제되지 않는다.

B를 적용할 때도 위와 같은 방식으로 **선택한 정확한 파일만** backup → 공개 링크/한계 설명 정리 → `.gitignore`의 `/docs/정확한이름.md` 등 추가 → `git rm --cached -- <정확한 파일>` 순서로 처리한다. `/docs/`, `/plan/`, `*.md` 전체 제외는 하지 않는다. 이미 B의 `trash` 파일도 함께 제외하기로 정했다면 개별 규칙 대신 `/trash/`로 통합할 수 있다.

공개 저장소 전체에 적용할 제외 규칙은 `.gitignore`가 적합하다. `.git/info/exclude`는 현재 clone에만 적용되는 개인 규칙이며 공유되지 않는다. 두 방식 모두 이미 추적 중인 파일을 자동으로 해제하지 않는다. `assume-unchanged`나 `skip-worktree`는 공개 HEAD에서 파일을 빼는 대체 수단으로 사용하지 않는다.

### 5.4 이 보고서의 공개 여부

이 보고서 자체는 저장소 관리용이며 데모의 필수 문서가 아니다. 면접관에게 내부 정리 계획까지 공개할 필요가 없다면, 검토 후 **이 파일도 같은 경로에 두고 로컬 전용으로 관리**하는 선택을 권한다. 현재는 사용자의 검토를 위해 `docs/파일_및_버전관리_정리_조사.md`로 생성했으며 별도 ignore 규칙은 추가하지 않았다. 아직 미추적이라면 `.git/info/exclude`에 이 정확한 경로를 추가하는 것으로 충분하고, 나중에 추적했다면 `git rm --cached`도 필요하다.

### 5.5 Git 이력과 복구의 경계

- `git rm --cached` + 커밋은 **새 HEAD**에서만 제외한다. 과거 커밋, 기존 브랜치·태그·PR diff, 다른 사람이 가진 clone에는 내용이 남을 수 있다. “과거 공개 흔적까지 제거 완료”라고 보고하면 안 된다.
- 과거 이력까지 지우는 재작성은 커밋 해시 변경·원격 강제 갱신·공동 작업자 동기화를 동반하는 별도 작업이다. 이번 요청의 문서 작성이나 향후 일반 추적 해제에 자동 포함하지 않는다. 과거 이력을 그대로 남기면서 최신 공개 트리만 정리하는 것이 기본 제안이다.
- 추적 해제 커밋을 받은 **다른 clone**에서는 기존 추적 파일이 제거될 수 있다. `--cached`가 원본을 남기는 보장은 그 명령을 실행한 현재 작업 폴더에 대한 것이다. 다른 작업 환경에도 개인 파일이 필요하면 해당 환경에서 먼저 백업한다.
- 커밋 전 추적 해제를 취소하려면 `git restore --staged -- <정확한 경로>`로 인덱스를 복구하고 추가한 ignore 규칙만 되돌린다. 작업 원본을 덮어쓰는 `git restore -- <경로>`와 구분한다.
- 이력에서 공개 파일을 다시 가져올 때는 개인 로컬 원본을 먼저 백업한 뒤 복구한다. `git clean -fdx`는 ignored 개인 파일까지 삭제하므로 정리 절차에 넣지 않는다.

### 6.3 삭제 적용 후 검증 계획 — 이번에 미실행

기존 `install/`에 남은 파일로 성공을 오판하지 않도록 **새 셸과 별도 빌드·설치 경로**를 사용한다. 아래 예시는 `/opt/ros/jazzy`만 먼저 source하고 기존 프로젝트 overlay는 불러오지 않은 셸을 전제로 한다. 별도 산출 경로가 생기므로 아래 `/tmp` 경로는 Git 공개 대상이 아니다.

```bash
source /opt/ros/jazzy/setup.bash
export GZ_VERSION=harmonic
audit_verify_root=$(mktemp -d /tmp/my_arm_cleanup_verify.XXXXXX)
colcon --log-base "$audit_verify_root/log" build \
  --build-base "$audit_verify_root/build" \
  --install-base "$audit_verify_root/install" --symlink-install
source "$audit_verify_root/install/setup.bash"
colcon --log-base "$audit_verify_root/log" test \
  --build-base "$audit_verify_root/build" \
  --install-base "$audit_verify_root/install"
colcon test-result --test-result-base "$audit_verify_root/build" --verbose
```

빌드 실패 시 이후 source/test로 진행하지 않는다. 위 예시는 단계별로 결과를 읽고 진행하는 명령이며, 테스트 실패를 이전 성공으로 덮지 않는다. 이어서 [기존 검증 절차](리팩토링시_활용위한_점검방법.md)를 이용해 아래를 **각각 기존 시뮬레이션 종료 후 새로 실행**한다.

| 검증 | 완료 근거 |
| --- | --- |
| 새 빌드 및 패키지 테스트 | 명령 종료 코드, 등록 테스트 결과, lint 결과를 분리 기록 |
| simulation·controller·joint states | controller 활성화, 팔·그리퍼 action, 최신 /joint_states, GraspSystem 로드 확인 |
| keyboard teleop | 별도 PTY에서 팔·그리퍼 동작, busy 입력 처리, 종료·취소 확인 |
| pick_grasp 단독 시험 | `STAGE4 GRASP TEST PASSED` 및 정상 시험 종료 확인 |
| 자동 Pick & Place | `STAGE5 PICK AND PLACE PASSED; waiting` 및 대기 상태 확인. 대기 중 Ctrl+C는 성공 로그와 구분 |
| demo + validate_planning | Gazebo 없이 계획 성공·충돌 대조 검사 결과 확인 |
| GUI | UR5/RG2 mesh·RViz 장면·물리 접촉 확인. headless 성공으로 GUI 성공을 대신하지 않음 |
